## 1. 目标与已对齐的理解

**目标：** 把现有 Rails 3.2 系统（`chineseschool/`）用其他框架重写，保持相同的业务逻辑，改为前后端分离、自动化运维，部署在单台 Ubuntu 云服务器。

**使用者与维护者：** 用户本人加 Claude（无固定团队）。

**成功标准：**
1. 费用、折扣、退款金额与旧系统在固定黄金用例上逐条一致（Q-11 修正的截止日后退款除外，该处按意图为 0）。
2. 每个角色能访问的功能与旧系统一致，且服务端默认拒绝、有对象级授权。
3. 注册高峰（约 150 人同时在线）下付款不重复、不丢、不错账。
4. 单机故障后，注册期 RPO ≤ 1 小时，RTO ≤ 4 小时。
5. 卡号不经过我们的服务器。

**范围外：** 田径功能、图书借阅功能（整体不重写）。对应的 7 张表在生产库中保留不碰、不迁移。

## 4. 整体结构与模块划分

**仓库布局：** 仓库根目录新增 `backend/`（NestJS）和 `frontend/`（React）。`chineseschool/` 旧代码原地保留、不改动。

**后端模块（按领域）：**

| 模块 | 职责 |
|------|------|
| `auth` | 登录、会话、找回密码、邀请令牌、旧哈希静默升级 |
| `access` | 用户、角色、权限码、教师/班级家长角色的自动推导 |
| `audit` | 审计日志 |
| `people` | 人员、家庭、地址 |
| `school-year` | 学年配置（费用、日期、开关） |
| `curriculum` | 年级、班级、按学年启停 |
| `enrollment` | 注册偏好、分班、教师/员工任课分配 |
| `fees` | 费用与折扣规则（纯函数，不依赖数据库和框架） |
| `payments` | 注册付款、网关（接口封装）、现场缴费、手工交易 |
| `withdrawals` | 退课申请、批准、退款规则（纯函数） |
| `instruction` | 期末成绩 |
| `documents` | PDF 表格 |
| `reports` | CSV 报表导出 |
| `notifications` | 邮件 |

**分层：** 每个模块分三层：控制器（HTTP、DTO 校验、声明所需权限码）→ 服务（用例、事务边界）→ 仓储（Prisma）。控制器之间不互相调用，跨模块只通过服务的公开接口。

**角色与领域的关系：** 角色只体现在权限码上。前端按角色组织导航和页面（见第 8 节），后端不按角色分目录。

**横切约定：** 可注入的"太平洋时间时钟"；金额只用整数分；权限守卫默认拒绝；付款提交带幂等键。

## 5. 认证、授权与审计

**认证**
- **会话：** 服务端会话。浏览器只持有一个 cookie（HttpOnly、Secure、SameSite=Lax），会话记录存在 PostgreSQL 的新增 `sessions` 表。不用 JWT：登出和强制下线必须立刻生效（FR-AUTH-02），存数据库即可做到，也不需要 Redis。
- **同源与 CSRF：** 前端静态文件和 API 由同一个反向代理提供，API 统一在 `/api` 下，不涉及跨域。写操作另带 CSRF 令牌头。
- **登录：** 用户名加密码，带限速和失败锁定。先验证 argon2id 哈希；没有则验证旧的 `SHA256(密码+盐)`，成功后升级（Q-08）。"登录后跳回原页面"由前端记住目标路径实现。
- **邀请和重置令牌：** 256 位随机数，数据库只存哈希，一次性、限时。旧 `timed_tokens` 表是明文存储，不再使用，新增 `auth_tokens` 表。

**授权**
- **权限码：** 稳定字符串，例如 `payments.in_person.record`。新增 `permissions` 和 `role_permissions` 表；`roles`、`roles_users` 沿用。旧 `rights` 表只读保留，用于 MIG-02 的旧权限到新权限码的映射。
- **默认拒绝：** 每个控制器方法必须声明 `@RequirePermission(...)` 或 `@Public()`，否则应用启动失败。
- **对象级检查：** 权限码之外，服务层按策略校验"这条数据是不是你的"。例如家长只能访问自己的家庭，教师只能访问自己任课的班级。每个接口有对应的越权（IDOR）测试。
- **自动推导角色：** 教师和班级家长角色随任课分配自动增删，与分配变更放在同一事务里。

**审计**
- 新增追加式 `audit_logs` 表，记录：操作人、时间（UTC）、动作、对象、来源 IP；附加信息中不放卡号、密码、令牌。
- 覆盖事件：登录失败、角色和权限变更、退款批准、手工交易、个人信息导出（含报表和名单类 PDF/CSV）。
- 应用数据库账号对该表只有插入权限。

## 6. 数据库衔接与金额、时间约定

**数据库衔接**
- **基线：** 以生产库的真实结构为准做 Prisma introspection，不用 `db/schema.rb`（迁移文件不完整，DATA-05）。把导出的结构作为基线迁移，标记为"已应用"，此后只做增量迁移。
- **不在模型里的表：** 7 张表（田径 5、图书 2）不进 `schema.prisma`。防止 Prisma 把它们当多余的表生成 `DROP`，用两道保险：
  1. CI 扫描每个迁移的 SQL，出现 `DROP`、`TRUNCATE`、删列即失败，除非人工标注放行。
  2. 两个数据库账号：迁移账号只在部署时使用；运行账号只有增删改查权限，不能改表结构，对那 7 张表没有任何权限，对 `audit_logs` 只能插入。
- **Rails 惯例的映射：** 复数蛇形表名用 `@@map` 保留，代码里用驼峰；无 `id` 的联结表（`families_children`、`rights_roles`、`roles_users`）用复合主键 `@@id`；非常规外键（`parent_one_id`、`paid_by_id` 等）显式写 `@relation`。
- **增量内容：** `sessions`、`auth_tokens`、`permissions`、`role_permissions`、`audit_logs`、幂等键表，以及 `users.password_hash_v2`。
- **可回退：** 迁移全是增量，旧 Rails 系统仍能在这个库上运行。旧 `password_hash`、`password_salt` 列保留到升级截止日，所以回退后老用户仍能用旧系统登录。

**金额**
- 全部是整数分，用 `Cents` 类型和辅助函数运算，lint 规则禁止浮点金额。API 传整数分，界面负责格式化。
- 百分比一律整数运算并写明取整方式。迟报折算为 `trunc(学费 × 3 / 4)`：旧代码是 `(学费 × 0.75).to_i`，0.75 在二进制浮点里精确，两者结果一致。
- 比例退款（0.9 在浮点里不精确，可能差 1 分）按 Q-11 先对旧系统实测再定取整方式。

**时间**
- 可注入的 `Clock` 服务，提供 `today()`（太平洋日期）和 `now()`。费用和退款规则是纯函数，"今天"作为参数传入，函数内部不得直接取系统时间。
- 太平洋日期用 IANA 时区 `America/Los_Angeles` 计算，正确处理夏令时。"某日收款"把太平洋的一天换算成 UTC 的半开区间 `[起, 止)`。
- 时间戳一律存 UTC。`date` 列读出后立刻转成纯日期值 `PacificDate`（`YYYY-MM-DD`），避免时区偏移一天。
- 测试通过注入冻结时钟控制"今天"，黄金用例覆盖日期边界。

## 7. API 约定

- **风格：** REST + JSON，统一放在 `/api/v1` 下。普通数据用资源路径，业务动作（批准退课、录入现场付款）用明确的动作路径。
- **只有写方法能改数据：** 修改只用 POST、PUT、PATCH、DELETE，GET 绝不产生副作用，没有通配路由（SEC-01）。
- **类型贯通：** NestJS 生成 OpenAPI 文档，前端据此生成 TypeScript 客户端类型。CI 检查生成的类型是否已更新，过期即失败。
- **输入校验：** 每个接口用 DTO 校验，未声明的字段一律丢弃（取代 `attr_accessible`）。
- **统一错误格式：** `{ code, message, details, requestId }`。状态码：未登录 401；无权限 403；"这条数据不是你的"返回 404（不让人探测别人的 id）；校验失败 422；幂等冲突 409。
- **幂等：** 付款提交等涉及金额的 POST 必须带 `Idempotency-Key` 头，服务端把结果存进幂等键表，重复提交返回同一结果。
- **文件下载：** PDF 和 CSV 是需要登录的 GET 接口，返回文件流，含个人信息的每次导出写审计日志。
- **限速与日志：** 全局限速，登录和找回密码更严；每个请求带 `requestId`；结构化日志自动过滤卡号、密码、令牌。

**支付集成：** 浏览器端把卡号直接发给 Authorize.net 换回一次性令牌，后端只用令牌发起扣款，数据库只存卡类型、末四位和交易号。支付封装在接口后面，便于更换网关。扣款以 `gateway_transaction.id` 作 `order_id`。返回码行为保留：1 通过、2 拒绝、其余（含 4 待审核）为 ERROR 并发运维告警。

## 8. 前端结构与错误处理

- **技术：** React + Vite + TypeScript，React Router 做路由，TanStack Query 管理请求，Ant Design 作界面库。
- **按角色组织：** 路由分组 `/parent`、`/registration`、`/accounting`、`/admin`、`/instruction`、`/communication`。首页的角色面板和导航由登录后 `/api/me` 返回的权限码列表决定。前端的权限判断只用来改善体验，真正的拦截始终在服务端。
- **语言：** 现有界面是英文，新系统默认英文，结构上预留多语言；中文姓名和中文 PDF 正常显示（NFR-01）。
- **付款页：** 网关脚本只在付款页加载，配合严格的 CSP 限制脚本来源。
- **错误处理：** 401 → 跳登录页，登录后回到原页面；403 → 提示无权限；422 的字段错误映射回表单字段；付款结果区分"通过 / 拒绝 / 出错 / 重复提交"四种状态，出错时可以安全重试（幂等键保证不重复扣款）。

## 9. 部署、CI/CD 与运维

**部署（单台 Ubuntu，Docker Compose）**
- **拓扑：** Caddy（自动申请和续期 Let's Encrypt 证书）→ `api` 容器 + 前端静态文件 + `postgres` 容器。数据库只在容器内网监听。
- **容器加固：** 非 root 运行、只读根文件系统、丢弃多余 capabilities，不暴露 Docker 守护进程。
- **主机加固：** Ansible 剧本落实 UFW（只开 80、443、SSH）、SSH 仅密钥登录且禁 root、Fail2ban、自动安全更新。剧本放仓库里，满足"可在新机器上快速重建"（OPS-07）。
- **密钥：** 环境变量文件权限 600、仅 root 可读，不入库；CI 里跑密钥扫描。
- **备份：** 平时每日加密 `pg_dump`；注册期启用 WAL 归档（优先 pgBackRest）；上传到异地对象存储；附恢复脚本，每学年演练一次。
- **监控：** `/healthz`、结构化日志、外部可用性探测、磁盘和证书到期告警，付款失败和邮件失败发告警邮件。
- **环境：** 本地开发（Compose 起 PostgreSQL 和收邮件的测试服务）、CI、生产三套。不设长期预发环境；迁移验证期间临时起一个独立实例，连脱敏副本。

**CI/CD（GitHub Actions + GHCR）**
- **每个 PR：** lint、类型检查、单元测试、连真实 PostgreSQL 的集成测试、OpenAPI 客户端类型是否过期、迁移 SQL 破坏性检查、密钥扫描、依赖和镜像漏洞扫描。
- **合并到主分支后：** 构建镜像并推送；部署需人工批准。部署时先自动备份，再用迁移账号执行增量迁移，启动新容器并做健康检查，失败自动回滚到上一版镜像。迁移全是增量，回滚镜像是安全的。

## 10. 测试策略

- **规则单元测试：** 费用、折扣、退款纯函数的所有分支，覆盖日期边界和取整，分支覆盖率要求 100%。
- **黄金用例（MIG-03）：** 用旧 Rails 代码对固定输入跑出金额，保存为 JSON 夹具，新系统逐条一致。专门覆盖：迟报 + 教师折扣（Q-10）、截止日后退款为 0（Q-11，同时记录旧系统实际输出）、折扣大于学费的负数边界。
- **权限矩阵测试：** 从路由表自动生成"每个接口 × 每个角色"的允许/拒绝断言，与 MIG-02 映射对照；另有越权（IDOR）测试。
- **集成测试：** 真实 PostgreSQL + 冻结时钟 + 假网关，覆盖付款事务、重复提交、返回码 1/2/3/4/未知；另有一条连沙箱的冒烟测试。
- **端到端（Playwright）：** 家长注册并付款、注册官分班、退课申请与批准三条主流程。
- **压测（k6）：** 150 并发家长走完整流程，满足 NFR-03 的验收要求。
